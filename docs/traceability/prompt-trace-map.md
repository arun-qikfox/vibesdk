# Prompt & Artifact Traceability (Cloudflare Agent)

This log links every major execution step in the Cloudflare Worker agent to the concrete prompt, source file, and the artifacts that are produced or consumed. Use it to audit which LLM prompt created a given output file, review, or preview.

| # | Step | Prompt Location | Input Payloads | Output / Side Effects |
|---|------|-----------------|----------------|-----------------------|
| 1 | **Template selection** | `worker/agents/planning/templateSelector.ts` (`systemPrompt` + `userPrompt`, see lines 31‑120) | - User query (`POST /api/agent`) <br> - Template list from `SandboxSdkClient.listTemplates()` <br> - Optional screenshots converted to base64 `data:` URLs | `TemplateSelection` JSON (`selectedTemplateName`, `reasoning`, `styleSelection`, etc.) streamed back to `CodingAgentController` and cached in DO state. |
| 2 | **Blueprint (PRD) generation** | `worker/agents/planning/blueprint.ts` (multi-section SYSTEM_PROMPT + multi-modal user message) | - Template file snippets (`TemplateDetails.files`) <br> - `inferenceContext` (user, agent, model configs) <br> - User query & images | - Streamed chunks through `initArgs.onBlueprintChunk` → NDJSON <br> - Parsed `Blueprint` object saved to Durable Object state and persisted to D1 (`AgentStateService.saveAgentSession`). |
| 3 | **Phase planning loop** | `worker/agents/operations/PhaseGeneration.ts` (`SYSTEM_PROMPT` emphasising UI polish) | - Current blueprint & code snapshot (`TemplateRegistry`) <br> - Outstanding issues (`IssueReport`) <br> - Pending user follow-ups | Returns `PhaseConcept` describing the next milestone. The result feeds into DO state and logs via `AgentExecutionLog` in D1. |
| 4 | **Phase implementation** | `worker/agents/operations/PhaseImplementation.ts` (`SYSTEM_PROMPT` for senior engineer + SCOF streaming config) | - `PhaseConcept` from step 3 <br> - Issues snapshot, user context, and optional images <br> - Previous file contents from sandbox hydration | Emits streaming SCOF events: <br> • `fileGeneratingCallback` → WebSocket `FILE_GENERATING` <br> • `fileChunkGeneratedCallback` → NDJSON/WebSocket diffs <br> • `fileClosedCallback` → marks file completion. Each completed file is written to the sandbox overlay (R2 object store) and optionally staged in KV for diff retrieval. |
| 5 | **Fast fixer (optional)** | `worker/agents/assistants/realtimeCodeFixer.ts` (prompts inside `FastCodeFixerOperation`) | Triggered when static analysis detects regressions or when implementation requests autofix. | Produces follow-up SCOF chunks that patch files before the phase closes; audit trail stored in `agentExecutionLogs`. |
| 6 | **Code review** | `worker/agents/operations/CodeReview.ts` (`SYSTEM_PROMPT` focusing on React issues) | - Current repo snapshot <br> - Phase outputs <br> - Static analysis + runtime logs | Creates `CodeReviewOutput` JSON (blocking issues, severity, remediation). Results broadcast over WebSocket, appended to `agentExecutionLogs`, and if blockers remain the loop re-enters step 4. |
| 7 | **Deployment instructions** | `worker/agents/operations/common.ts:getSystemPromptWithProjectContext` (shared prompt fragment) & `worker/agents/services/implementations/ProjectSetupAssistant.ts` | - Project blueprint & package manifest <br> - Sandbox telemetry | Yields setup commands (`npm install …`, env notes) that are queued via `executeCommands()`; outputs recorded in D1 `agentPhases` table. |
| 8 | **Preview deployment** | `worker/services/sandbox/remoteSandboxService.ts` (REST call to container) | - Generated source files (SCOF outputs) streamed to sandbox <br> - `sandboxSessionId` | Container builds the project, stores build artifact in R2, and returns a signed preview URL. `CodingAgentController.deployPreview` streams the URL to the client and the DO logs the deployment in `appDeployments` (D1). |
